# 驱动兼容性

本文描述随 `pvr-psp2-sys` 提供的驱动源码。只更新 Rust 接口库不会替换设备上的 `.suprx`；运行时行为取决于实际部署的模块版本。构建和部署方式见 [README](../README.md)。

## 程序切换与 shader 寿命

当前 `UseProgram` 在有效切换程序后刷新两个已链接的着色器阶段，不依赖 shader 是否仍挂接在 program 上。应用可在链接后 detach shader，并按 GLES 对象引用规则删除对象。重复绑定同一程序不重新刷新；无效绑定保留原程序状态并归还查询引用。

旧实现根据前后程序的 shader 挂接指针决定刷新哪些阶段。链接后 detach 可能使 GPU 沿用先前阶段。需要兼容这种旧模块时，可保留挂接关系，并用 `glDeleteShader` 标记延迟删除；相关引用随 program 删除而释放。

## 异步纹理上传

当前 `PrepareHWTQTextureUpload` 将紧密行输入复制到驱动拥有的缓冲，不在调用返回后继续读取应用的原始像素指针。异步缓冲释放前等待相应传输完成；清理队列满时也先等待相关工作，再回收内存。调用者的像素内存不建立额外 GPU 映射，上传返回后可正常复用或释放。

旧模块的部分 `glTexSubImage2D` 路径可能将应用指针直接提交到硬件传输队列。兼容旧模块的应用需要保留输入数据，直到依赖该纹理的采样与绘制完成；仅等待一次不依赖该纹理的绘制不足以证明上传已结束。

异步 CPU 纹理工作使用固定工作线程和有界队列；队列满或线程不可用时改为同步执行。开始共享上下文前会等待现有任务完成，共享上下文的 CPU 纹理工作同步执行。`SwTexOpThreadNum` 上限为 4，`SwTexOpMaxUltNum` 控制任务槽数，上限为 4096；`SwTexOpCleanupDelay` 不再控制清理周期，回收由任务完成事件触发。

## 纹理更新与缓存

- 支持的单块 stride／tiled／POT twiddled 纹理，在没有待完成 GPU 工作时可直接更新局部区域；小块 stride 更新可省去传输暂存和同步对象申请。其他情况保留完整更新路径。
- 不旋转或仅翻转 Y 轴的 tiled／POT twiddled 读回只转换请求区域。
- BC1 / BC3 完整上传在非 mipmap 过滤模式下直接复制到最终设备存储。
- 非共享上下文可在忙碌时更换缓冲区存储，并将删除的缓冲区保留到 GPU 使用完成。
- 顶点和索引缓冲区通过 KRM 跟踪 GPU 使用寿命，不占用独立同步对象名额；纹理上传和渲染表面仍保留所需同步。
- 着色器缓存键区分着色器阶段、精度设置和编译版本；旧缓存条目会自然失效。

## 分配与编译

- 渲染目标创建、调整和唤醒路径检查内存申请与注册失败，并回收该次操作已取得的资源。
- 同步对象申请失败时清空输出指针；设备内存释放后不再读取已释放的描述符。
- 纹理堆扩容后的首次分配失败时，撤销新块的 GPU 映射并释放内存；失败操作不增加堆内分配计数。
- GPU 扩展初始化检查系统模块信息，新堆申请成功后才替换旧堆。
- SGX543 编译器按常量的原始位值搬运奇数编号向量硬件常量，避免标量 `MOV` 使用不支持的源寄存器。

`MaxQueuedRenders = 3` 表示单个渲染目标的队列深度，不是可创建的 FBO 数量上限。

纹理存储在 CDRAM、USER_NC 和回收重试均失败后，日志输出 `[PVR][TEXALLOC]` 的尺寸与申请字节数，以及四条 `[PVR][ALLOC]` 的失败步骤和原始错误码。`kernel-block`、`gpu-map`、`mspace-alloc`、`descriptor`、`sync-object` 分别表示内核内存块、GPU 映射、堆内分配、驱动描述符和同步对象；成功回退不输出这些日志。

`[PVR][HEAPS]` 中的 `libc_*` 是 Sony libc 的堆统计，`unc_free`、`cdram_free` 是驱动已持有堆内的空闲字节数。它们与内核空闲内存、应用纹理预算分别统计，均不能代表最大可分配连续块。

`[PVR][BUFALLOC]` 记录缓冲区两种内存池均分配失败时的目标、字节数、对齐，以及各池的失败步骤／错误码／扩容块大小。`sync-object/0xB9` 表示同步对象名额耗尽，与像素内存剩余字节数不同。

## 存储与回收策略

新建、单层、非 mipmap 的原生像素格式纹理，可直接取得最终设备存储。空输入无需分配并复制同尺寸主机图像；紧密行输入在调用返回前写入最终存储。带行填充、格式转换、多层和其他不适用情况继续使用通用路径。首次 framebuffer 复制可直接使用硬件传输，硬件路径不支持时回退到原有实现。

异步上传按纹理索引查询在途工作，另设 8 MiB 输入字节预算；任务槽或预算不足时同步执行。退休缓冲按传输提交批次等待；没有新硬件传输的 CPU 工作不会重复等待传输队列。共享上下文保留全局传输等待。

纹理只在硬件传输需要时申请同步对象。已释放纹理的同步对象在确认传输完成后可进入最多 8 项的复用池；仍忙碌的对象不进入池。删除纹理时只提交引用该纹理的未提交绘制，无法确定对应资源时保留完整提交路径。

每个可扩展纹理堆最多保留一个不超过 8 MiB 的空闲映射块。新申请无法利用该块时先释放它。内存申请失败时优先回收已完成的 ghost、暂存池和空闲块，再重试；仍失败时，按申请量回收可用的 CDRAM 纹理。该策略不对活跃 USER 纹理执行没有池容量收益的回读。

每个渲染表面的 PDS/USSE 命令存储通过 GPU 完成偏移控制环形缓冲复用，不再各自申请未参与提交的同步对象；表面同步对象和状态更新内存继续保留。

对已分配、尺寸和格式均未改变的渲染缓冲，重复 `glRenderbufferStorage` 保留其存储和渲染目标。应用仍应按照 GLES 规则将重定义后的内容视为未定义。

### 分组对照构建

原生 CMake 参数 `PVR_OPT_MASK` 默认 `1023`。位 0–9 分别控制：空纹理直接分配、像素直接初始化、首次 GPU 复制、stride 局部更新、空闲大块复用、异步队列预算与等待合并、同步对象按需申请与复用、按消费者提交、渲染表面资源精简及同尺寸缓冲复用、限量纹理回收。清除对应位可单独关闭该组优化，例如 `-DPVR_OPT_MASK=1022` 关闭第一组。

该参数用于定位性能或兼容性变化；关闭全部位并不等同于恢复上游源码，既有正确性修复和基础设施仍然保留。`[PVR][SURFACE]` 在渲染目标、表面同步及命令缓冲申请失败时记录阶段、原始错误和申请量；RT add 失败另有 `[PVR][RTALLOC]` 尺寸及队列配置。独立探针可用 `-DPVR_PROBE_DIAGNOSTICS=ON` 将这些失败记录到 `ux0:/data/pvr-driver-probe/driver-failure.csv`，普通构建默认不写文件。

## BC1 / BC3 纹理扩展

驱动通过 `GL_KRKR_texture_compression_bc` 暴露有限的 BC 纹理支持。使用前应查询扩展字符串；该扩展不等同于完整的 `EXT_texture_compression_s3tc`。

| 格式编号 | 格式 | 块大小 |
| --- | --- | --- |
| `0x60000001` | BC1 RGB，采样 Alpha 固定为 1 | 每个 4×4 块 8 字节 |
| `0x60000002` | BC3 RGBA，独立 Alpha | 每个 4×4 块 16 字节 |

上传数据必须满足：

- `GL_TEXTURE_2D`、level 0，完整纹理上传。
- 宽高分别为 2 的幂且至少为 8，仍受驱动纹理尺寸上限约束。
- 块内使用标准 BC 小端数据；块间使用 SGX543 的 **Y 位优先 Morton 顺序**，不能直接提交按行排列的 BC 块。

压缩纹理不支持 subimage、自动 mipmap、作为 FBO 附件或直接复制写入。需要修改内容时，应使用 RGBA 纹理或重新准备完整的压缩数据。

## 验证范围

构建时检查原有导出编号，主机故障注入测试覆盖分配失败、回收、重试、释放后访问及程序切换引用处理。GPU 传输、模块加载和实际像素结果仍须用所部署的模块在 Vita 上验证。
